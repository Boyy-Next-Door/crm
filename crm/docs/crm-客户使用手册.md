## 1. 开始使用

两个团队各用一套完全独立的系统：数据、用户、配置互不相通，一个团队看不到另一个团队的任何内容。

### 访问地址

| | 地址 |
|---|---|
| **团队 A** | `http://117.50.226.162/a` |
| **团队 B** | `http://117.50.226.162/b` |

浏览器里输入这个地址即可，会自动跳转到登录页。建议存为书签。两个地址对应两套独立系统，请确认自己属于哪个团队。

> 短地址跳转的是 `/login` 而不是 `/crm`：Frappe 对未登录用户访问 `/crm` 会返回「没有权限」页，而 `/login` 未登录时给登录页、已登录时自动跳到 `/crm` —— 两种情况都对。

### 首次登录

1. 打开所属团队的地址，进入登录页。
2. 输入管理员分配给你的**邮箱**和**密码**。如果你收到的是邀请邮件，点邮件里的「接受邀请」按钮设置自己的密码。
3. 登录后右上角点头像 → **Settings（设置）**，立即修改初始密码。
4. 在同一处确认**姓名**和**头像**已填写 —— 线索分配、@提醒都靠这个识别你。

### ⚠️ 重要：不要在同一个浏览器里同时登录两套系统

两套系统在同一个 IP 上，**cookie 不按端口隔离**（RFC 6265，端口不参与 cookie 作用域），浏览器的登录凭证会互相覆盖。先登 A 再登 B，会导致 A 那边掉线、操作报错「您无权访问此资源」。

如果确实需要同时看两套（比如你是管理员），请用**两个不同的浏览器**，或者其中一套用**无痕 / 隐私窗口**。

## 2. 界面总览

登录后左侧是主导航，日常工作基本围绕「线索」和「商机」两个列表展开。

| 入口 | 作用 | 谁常用 |
|---|---|---|
| **线索 Leads** | 还没确认购买意向的潜在客户，销售跟进的起点 | 全员 |
| **商机 Deals** | 已确认有意向、正在推进成交的机会，带金额和预计成交日期 | 全员 |
| **联系人 Contacts** | 具体的人：姓名、电话、邮箱、职位 | 全员 |
| **组织 Organizations** | 客户公司：行业、规模、官网、年营收 | 全员 |
| **任务 Tasks** | 待办事项，可挂在某条线索或商机下 | 全员 |
| **备注 Notes** | 自由记录，同样可挂在线索或商机下 | 全员 |
| **通话记录 Call Logs** | 电话沟通记录（接入电话系统后自动生成） | 全员 |
| **日历 Calendar** | 按时间看自己的任务和安排 | 全员 |
| **仪表盘 Dashboard** | 线索转化、商机分布、业绩概览 | 主管 |
| **数据导入 Data Import** | 从 CSV 批量导入线索、商机、联系人、组织 | 经理 / 管理员 |
| **设置 Settings** | 用户、角色、邮箱、SLA、自定义字段 | 管理员 |

### 列表页的三件套

线索、商机、联系人等列表页顶部都有这三个控件，用熟了效率差别很大：

- **筛选 Filter** —— 按状态、负责人、来源、创建时间等条件缩小范围。
- **排序 Sort** —— 常用「最后修改时间倒序」看最近有动静的，或「创建时间正序」清理积压。
- **视图切换** —— 列表视图适合批量处理，**看板视图**按状态分列、可拖拽，适合看整体推进情况。筛选好的条件可以**存为自定义视图**，下次一键调出。

## 3. 线索管理

线索是销售流程的入口。一条线索代表「一个可能有需求的人」，确认有意向后转成商机。

### 线索的七种状态

| 中文 | 系统值 | 含义 |
|---|---|---|
| 新建 | `New` | 刚进系统，还没联系过 |
| 已联系 | `Contacted` | 已经触达，等待反馈 |
| 培育中 | `Nurture` | 暂时没预算或没需求，但值得长期跟 |
| 已验证 | `Qualified` | 确认符合目标客户画像、有真实需求 |
| 已转化 | `Converted` | 已转成商机 |
| 不合格 | `Unqualified` | 明确不符合目标客户画像 |
| 无效 | `Junk` | 空号、错填、广告骚扰 |

正常路径是 **新建 → 已联系 → 已验证 → 已转化**。

> **为什么要认真标状态**
> 状态不只是给自己看的。看板视图、仪表盘的转化率、主管的团队视图，全部基于状态统计。随手留在「新建」不动，等于这条线索在所有报表里都不存在。

### 新建线索

点线索列表右上角**「+ 新建」**。必填的只有姓名，但建议至少补齐：

- **手机号 / 邮箱** —— 没有联系方式的线索没有意义
- **组织** —— 客户公司名，填了之后系统会尝试自动补全行业、规模等信息
- **来源** —— 网站、展会、老客户推荐、电话陌拜等，用于后续分析获客渠道效果
- **负责人** —— 不填默认是创建人自己

### 日常跟进

点开任意一条线索，右侧是详情，左侧是活动区，跟进动作都在这里完成：

| 标签页 | 用途 |
|---|---|
| 活动 Activity | 系统自动记录的所有变更历史 |
| 邮件 Emails | 直接在系统里收发，自动留痕 |
| 评论 Comments | 内部讨论，可 @ 同事，客户看不到 |
| 备注 Notes | 沉淀客户背景、需求要点 |
| 任务 Tasks | 下一步动作 + 截止时间 |
| 通话 Calls | 电话沟通记录 |

> **养成一个习惯**
> 每次跟进结束，做两件事：**更新状态**，**建一个带截止日期的下一步任务**。这两步做到位，线索就不会漏掉，主管也不用追着问进度。

### 转为商机

确认客户有明确采购意向后，在线索详情页点**「转为商机 Convert to Deal」**。系统会：

- 创建一条新商机，把组织和联系人信息带过去
- 自动创建或关联对应的**联系人**和**组织**记录
- 把原线索标记为**已转化**（线索不会被删除，历史记录保留）

## 4. 商机管理

商机代表一笔正在推进的生意，比线索多了金额、赢率和预计成交日期。

### 商机的七个阶段

| 中文 | 系统值 |
|---|---|
| 资格确认 | `Qualification` |
| 演示/方案 | `Demo/Making` |
| 报价 | `Proposal/Quotation` |
| 商务谈判 | `Negotiation` |
| 准备成交 | `Ready to Close` |
| 赢单 | `Won` |
| 输单 | `Lost` |

### 三个关键字段

| 字段 | 含义 | 为什么重要 |
|---|---|---|
| **年度合同金额** | 这笔生意的预计金额 | 业绩预测的基数 |
| **赢率 Probability** | 成交把握，百分比 | 金额 × 赢率 = 加权预测 |
| **预计成交日期** | 预计签约的时间 | 决定这笔单算在哪个周期 |

这三个字段随着阶段推进要**持续更新**。停在初次录入的数字不动，预测就没有参考价值。

### 关单

成交后状态改为**赢单**。丢单时改为**输单**，并在**输单原因**里如实填写（价格、竞品、需求不匹配、预算取消等）。输单原因是后续复盘最有价值的数据，别图省事跳过。

### 看板视图

商机列表切到**看板视图**，七个阶段横向排开，卡片可以直接拖拽换阶段。团队周会上过管道，用这个视图最直观。

## 5. 批量导入数据

把已有的客户表格批量导进系统。此功能需要**销售经理**或**系统管理员**权限。

**入口在左侧主导航的「数据导入」**（在「通话记录」下面），不在设置里。也可直接访问 `/crm/data-import`。普通销售用户看不到这个入口。

### 导入顺序很重要

```
组织  →  联系人  →  线索  →  商机
```

线索和商机里会引用组织名称。如果组织还不存在就先导线索，会报错 `Could not find Organization: XXX`。按上面的顺序来可以避免绝大多数导入失败。

### 操作步骤

1. 左侧主导航点**「数据导入」**。
2. **下载模板**。可以单独下某一类的 CSV，也可以下载打包 zip —— zip 里额外有一份 `字段说明_README.html`，列出每个字段的中文含义、类型、是否必填、可选值。
3. 用 Excel 打开模板，**删掉示例行**，填入真实数据。**第一行英文表头必须原样保留**，系统靠它匹配字段。
4. 另存为 **CSV（UTF-8）** 格式。
5. 先拿 **5–10 条**数据试导一次，确认字段都进对了位置，再上传完整表格。
6. 上传文件，选择对应的数据类型，点开始导入。导入结果页会逐行显示成功或失败原因。

### 线索模板的字段

| CSV 列名 | 中文含义 | 必填 | 填写说明 |
|---|---|---|---|
| `first_name` | 姓 | **是** | 如「张」 |
| `last_name` | 名 | | 如「三」 |
| `email` | 邮箱 | | 系统不校验重复 |
| `mobile_no` | 手机号 | | 纯数字，别带空格或短横线 |
| `organization` | 公司名称 | | 建议先导入组织表 |
| `job_title` | 职位 | | 自由填写 |
| `industry` | 行业 | | 必须是系统里已有的行业值 |
| `source` | 来源 | | 如 `Website`、`Referral`、`Exhibition` |
| `status` | 状态 | | 如 `New`、`Contacted`、`Nurture` |
| `no_of_employees` | 员工规模 | | 如 `1-10`、`11-50`、`51-200` |
| `annual_revenue` | 年营收 | | 纯数字，不要千分位逗号 |
| `territory` | 区域 | | 可留空 |
| `lead_owner` | 负责人 | | 填系统里的用户邮箱，留空则归导入人 |

### 导入失败排查

| 报错 | 原因 | 怎么改 |
|---|---|---|
| `Could not find X: Y` | 引用的关联记录不存在 | 先建/先导那条记录，或把该列留空 |
| 数字字段报错 | 填了 `1,000,000` 这种千分位 | 改成 `1000000` |
| 日期字段报错 | Excel 自动改成了 `12/31/2026` | 统一改成 `2026-12-31`，并把单元格设为文本格式 |
| 中文变乱码 | 另存时编码不是 UTF-8 | Excel 里选「CSV UTF-8（逗号分隔）」 |
| 状态/来源值不认 | 填了系统里没有的选项 | 先在界面上手工建一条，看下拉里的准确值 |

## 6. 用户与权限

> 本节面向**管理员**。

### 三种角色

| 角色 | 能做什么 | 给谁 |
|---|---|---|
| **Sales User**<br>销售用户 | 创建和管理线索、商机、联系人、组织、任务 | 一线销售 |
| **Sales Manager**<br>销售经理 | 在销售用户基础上，可查看下属数据、配置团队相关设置、使用数据导入 | 销售主管 |
| **System Manager**<br>系统管理员 | 全部权限：用户管理、系统设置、数据导入、自定义字段 | 1–2 人即可 |

### 添加用户

进入**设置 → 用户管理**，点**「邀请用户」**，填邮箱并选择角色。对方会收到一封中文邀请邮件，点击链接自行设置密码。

邀请邮件需要系统先配好发件邮箱（见第 7 节）。没配的话，改用直接创建用户并手工告知密码的方式。

> **两套环境共用一个发件邮箱时**，两封邀请信的发件人和标题完全一样，只有链接里的端口不同（A 是 `:8081`，B 是 `:8082`），邮件客户端还可能把它们折叠成同一个会话。同一个人被邀请到两套时，注意别点错。

### 销售层级

如果希望**销售经理能看到下属的线索和商机**，在**设置 → 用户层级（User Hierarchy）**里启用并搭建汇报关系树。

- 启用后：销售经理可见自己 + 所有下属的数据；销售用户只可见自己的
- 拖拽行可以调整汇报关系，规则是上级角色不能挂在下级角色之下
- 随时可关闭，关闭后层级树会保留，重新启用即恢复
- 把人从层级树移除，不等于删除用户，只是不再套用层级可见性规则

### ⚠️ 上线前建议调整的一项默认权限

系统默认允许**销售用户删除线索和商机**（这是 Frappe CRM 上游默认值）。如果不希望一线人员能删数据，请在角色权限里关掉 Sales User 对这两类数据的删除权限，改为只允许标记为「无效 / 输单」。

## 7. 系统设置

> 本节面向**管理员**，多数只需在上线时配置一次。

### 已经配好的

| 项目 | 当前值 |
|---|---|
| 界面语言 | 简体中文（新用户默认即为中文） |
| 时区 | Asia/Shanghai |
| 货币 | CNY 人民币 |
| 日期格式 | yyyy-mm-dd |
| 邮件模板 | 邀请邮件已中文化 |

### 需要你配置的

- **发件邮箱** —— 设置 → 邮件账户，加一个 SMTP 账号（企业邮箱/腾讯/阿里云均可），勾选「启用发件」和「默认发件」。**用授权码而不是登录密码。** 配好之前，邀请邮件和系统通知都发不出去。
- **收件邮箱**（可选）—— 配置后客户回信会自动归档到对应线索/商机下。**注意：两套环境不能共用同一个收件邮箱**，否则会互相抢邮件、重复建记录。
- **线索来源 / 行业 / 区域** —— 系统自带一批英文选项，建议按自己的业务增删，保持列表精简。
- **自定义字段** —— 设置 → 自定义，可给线索和商机加自己需要的字段。建议先用一两个月再决定加什么，避免一开始就堆一堆没人填的字段。
- **SLA 响应时效**（可选）—— 设定新线索必须在多长时间内首次响应，超时会高亮提醒。
- **分配规则**（可选）—— 新线索按规则自动分配给销售，省去手工派单。

## 8. 使用注意事项

### 安全

- 当前通过 **HTTP** 访问（地址栏无锁标志），密码和数据在网络上是明文传输的。请**仅在公司内网或可信网络下使用**，不要在公共 WiFi 下登录。
- 不要使用弱密码，不要多人共用同一个账号 —— 共用账号会让所有操作记录失去追溯意义。
- 管理员账号（Administrator）只用于系统配置，日常业务请用各自的实名账号。

### 数据

- 两套环境**数据完全独立**，不会互通，也无法互相查看。需要合并统计请联系管理员。
- 删除操作**不可恢复**。不再跟进的线索请标记为「无效」或「不合格」，不要删除 —— 保留下来对分析获客质量有价值。
- 请确认管理员已配置**每日自动备份**。

### 浏览器

- 推荐 **Chrome** 或 **Edge** 最新版本，不支持 IE。
- 同一浏览器**不要同时登录 A、B 两套系统**（原因见第 1 节）。
- 页面出现异常时，先试**强制刷新**（Windows: `Ctrl+F5`，Mac: `Cmd+Shift+R`）。

### 遇到问题

反馈问题时，请一并提供以下信息，能大幅缩短排查时间：

- 你用的是**哪套环境**（A 还是 B）和**哪个账号**
- 出问题的**页面地址**（浏览器地址栏完整复制）
- **操作步骤**：点了什么，期望什么结果，实际什么结果
- **报错截图**，要包含完整的错误提示文字
- 大致的**发生时间**，便于对照服务器日志
